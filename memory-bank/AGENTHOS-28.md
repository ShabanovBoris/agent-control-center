# AGENTHOS-28: подсветка выбора в TUI-агентах

Статус: сделано и слито — PR [#20](https://github.com/ShabanovBoris/agent-control-center/pull/20),
squash `f6cd10e`, Gate `pass` без блокеров. Создана после приёмки AGENTHOS-26.

## Причина и исправление

PTY терминалов панели наследует окружение процесса AHP-хоста, а хост запускается из
agent-раннера с `TERM=dumb`, `NO_COLOR=1`, `CLICOLOR=0`, `CLICOLOR_FORCE=0`, `FORCE_COLOR=0`,
`CI=1`. Из-за этого TUI на lipgloss/termenv/colorprofile (`kent`) и Node-TUI выбирают
Ascii/NoColor: выбранный пункт диалога не подсвечивается. `src/ui/TerminalEmulator.tsx`,
`server/terminal-stream.ts` и клавиши были исправны: SGR в панели рисуется, `ArrowDown`
в чистом окружении переносит подсветку.

В AHP 1.1.0 у `CreateTerminalParams` нет поля `env`, поэтому задать окружение отдельному PTY
нельзя. Чиним на единственной общей точке — лаунчерах хостов:

- `server/terminal-env.ts` — `TERMINAL_ENV_UNSET`, `TERMINAL_ENV_SET`, `terminalEnv(env, overrides)`;
- `scripts/start-responses-host.ts` — env дочернего `code agent host` строится через `terminalEnv`
  (сам wrapper по-прежнему видит ключи провайдера и свой журнал);
- `scripts/start-host.sh` — `unset NO_COLOR CLICOLOR CLICOLOR_FORCE FORCE_COLOR CI`,
  `TERM=xterm-256color`, `COLORTERM=truecolor` до `exec "$CODE"`.

Внутри PTY `TERM` выставляет сам хост (в замерах при `TERM=dumb` у хоста PTY всё равно
получал `xterm-256color`); остальные переменные PTY наследует от процесса хоста.
Лаунчеры нормализуют именно env хоста.

## Замеры (kent v2.14.0, codex v0.163.0, нативный PTY с чистым HOME/PATH)

Точное число SGR зависит от окна захвата и размера PTY (в разных прогонах 52–120), поэтому
в таблице оно имеет смысл только как «есть/нет»; устойчиво воспроизводится сама escape-
последовательность выбранного пункта.

| Окружение | SGR на стартовом экране `kent` | Что видно |
| --- | --- | --- |
| `TERM=xterm-256color`, `COLORTERM=truecolor` | есть, truecolor (`38;2;…`) | выбранный пункт `\x1b[1;38;2;48;133;252m◈ Create a new session` |
| грязное (5 переменных + `TERM=dumb`, `COLORTERM=`) | 0 | выбора цветом нет |
| только `NO_COLOR=1` / только `CLICOLOR=0` / только `CI=1` | 0 | каждая сама отключает цвет |
| только `CLICOLOR_FORCE=0` / только `FORCE_COLOR=0` | есть, truecolor | цвет есть |
| `TERM=dumb` + `COLORTERM=truecolor` | truecolor есть | `TERM=dumb` сам по себе не решает |
| `TERM=xterm-256color` без `COLORTERM` | есть, 256 цветов (`38;5;…`) | выбранный пункт `\x1b[1;38;5;33m`, хуже, чем truecolor |

`ArrowDown` в чистом окружении добавляет ~315 байт перерисовки и переносит SGR выбранного пункта.
`codex --help`: чистое окружение — 136 SGR, грязное — 0. `CODEX_HOME=$(mktemp -d) codex`
(login-пикер): чистое — выбранная строка `\x1b[38;5;6;49m> 2. Sign in with Device Code`,
после `ArrowDown` подсветка переезжает; грязное — цветового SGR нет.

Поправка к раннему Recon: утверждения «0 SGR при отсутствующем `NO_COLOR`» и «на стартовом экране
0 SGR в любом окружении» не воспроизвелись на текущей сборке — нулевой результат давало грязное
окружение (в частности `CI`/`CLICOLOR`) и методика замера. Пустой `NO_COLOR=` цвет не отключает,
`NO_COLOR=0` — отключает; поэтому переменная удаляется, а не выставляется пустой.

## Проверки

- `npm test` — новый `server/terminal-env.test.ts`: unit на `terminalEnv` (вход не мутируется,
  `overrides` применяются, `TERM`/`COLORTERM` не перебиваются) и запуск настоящего
  `scripts/start-host.sh` из временной копии со stub-CLI (`exec /usr/bin/env -0`): грязный env
  на входе, на выходе только `TERM=xterm-256color`, `COLORTERM=truecolor` и без пяти переменных.
  Тест падает, если убрать любую строку `unset`/`export` (проверено вручную: без `unset`
  `NO_COLOR` и `CI` доезжают до stub).
- `e2e/terminal-ansi.spec.ts` — SGR из mock-хоста (`\x1b[32m$`) доезжает до DOM xterm
  (`.xterm-fg-2`), то есть кадры `terminalData` и эмулятор байты не теряют.
- Живьём (стенд `npm run up`, панель `http://127.0.0.1:5173/#terminal`, хост local):
  `ps eww` у всех трёх хостов показывает `TERM=xterm-256color` и `COLORTERM=truecolor`, пяти
  переменных нет; внутри PTY `env` отдаёт `TERM=xterm-256color` и `COLORTERM=truecolor`;
  `kent` рисует выбранный пункт `rgb(48,133,252)` (`#3085fc`), после `ArrowDown` подсветка
  переезжает на следующую сессию, после `ArrowUp` возвращается; `CODEX_HOME=$(mktemp -d) codex`
  показывает login-пикер с выбранным пунктом `xterm-fg-6` (cyan) и переносит его по стрелкам.
  Проверка шла Playwright-скриптом по живому стенду (`.local/live-check.mjs`, вне репозитория):
  снимались inline-цвета и классы span'ов xterm до и после нажатий.
- Наблюдение по рестарту: `npm run restart:services` на стенде под `up` останавливает весь стенд —
  супервизор видит SIGINT-завершение хоста как падение («Запуск прерван из-за ошибки»), после чего
  нужен `npm run up`. Для этой задачи env-фикс применяется именно рестартом хостов; стенд поднят
  заново и проверен (все три хоста `connected`, web 200).

## Граница и остаточные риски

- Прямой `code agent host` в обход лаунчеров остаётся без гарантии — записано в README.
- Уже запущенный хост сохраняет старое окружение до рестарта хостов; на стенде под `up`
  `npm run restart:services` останавливает весь стенд (см. «Проверки»), поэтому нужен новый `npm run up`.
- `CI` снимается у всего процесса хоста: в репозитории его читает только `playwright.config.ts`,
  но env инструментов агента внутри хоста отдельно не проверялся (они пишут в pipe, а не в TTY).
- `TERM_PROGRAM` не нормализуется: на цвет проверенных TUI не влияет.
- Форсированные `xterm-256color`/`truecolor` верны, пока панель — единственный клиент этих
  локальных хостов.

## Симптом от владельца

«Запускаю `kent`, когда нужно что-то выбрать, оно не подсвечивается при переключении».
То есть в диалоге выбора TUI не видно, какой пункт активен.

## Что измерено (воспроизводимо)

Стенд поднят (`npm run up`), терминал открывается на `#terminal`. Измерения шли двумя путями:
перехват кадров `terminalData` в браузере и отдельный нативный PTY на той же машине.

**ANSI-рендер в панели исправен.** `printf` с `\033[41m` (красный фон), `\033[7m` (reverse),
`\033[48;5;62m` (256-цветный фон) рисуются корректно: xterm.js ставит `xterm-bg-1`,
`xterm-bg-257`, `xterm-bg-62`, `getComputedStyle` отдаёт реальные цвета
(`rgb(204, 0, 0)`, `rgb(95, 95, 215)`). Эмулятор и тема не при чём.

**Опровергнуто: «`kent` на стартовом экране не шлёт ни одной SGR-последовательности».** Так
выглядели замеры из окружения раннера (`TERM=dumb`, `NO_COLOR=1`, `FORCE_COLOR=0`, `CI=1`):
0 SGR на ~11-13 КБ вывода, из CSI только `\x1b[K` (53 раза), `?25l/h`, `H`, `2J`, `2K`,
`?1049h/l`, `?2004h/l`, `?1007h/l`, `?1002l`, `?1003l`, `?1006l`, OSC-запросов ноль. В чистом
окружении тот же экран даёт SGR (52–120 в зависимости от окна захвата) и `OSC 11` — см.
«Замеры» и «Итог». Вывод «от окружения это не зависит» неверен: выбор Ascii/NoColor делает
как раз окружение.

**Клавиши в грязном окружении.** `Tab` вызывает полную перерисовку списка (содержимое меняется),
`ArrowDown` (`\x1b[B`) не даёт в ответ ни одного байта. `Ctrl+P`, `Ctrl+K`, `?`, `Enter` на
«Create a new session» — во всех случаях SGR = 0. В чистом окружении `ArrowDown` добавляет
~315 байт перерисовки и переносит SGR выбранного пункта.

## Чего так и не проверяли

Настоящий диалог выбора внутри TUI (пикер модели, workflow, подтверждение) не открывался —
смотрели стартовый экран списка сессий и реакцию на отдельные клавиши. Вторым TUI взят `codex`
(login-пикер), полностью пройденный диалог подтверждения не проверялся.

## Порядок работы (первоначальный план — выполнен иначе)

План был: снять эталон в iTerm/Terminal.app, сравнить окружение PTY, при совпадении симптома
признать это поведением `kent` и не трогать `TerminalEmulator.tsx`. Он устарел: эталон в iTerm
не понадобился, потому что сравнение окружений сразу дало разницу — раннер выставлял пять
переменных, отключающих цвет. Пункт «если в iTerm подсветки тоже нет — это поведение `kent`»
был бы ложным выводом: iTerm, запущенный из того же раннера, показал бы то же самое.
`src/ui/TerminalEmulator.tsx` по цвету так и не менялся — но не потому, что этого нельзя было
делать, а потому что он был исправен.

## Смежное, которое оказалось корнем

Ранняя запись отделяла наследование окружения стендом (`NO_COLOR=1` от родительского процесса,
видно в env хоста `local`, backend и `up`) как «смежное, но отдельное» и утверждала, что на `kent`
это не влияет. Именно это и было причиной — числа в «Замерах» и «Итоге» ниже.

## Итог: что было на самом деле (замеры сессии 589)

Исходная гипотеза задачи («панель ломает ANSI») и промежуточный вывод Recon («kent вообще не
шлёт SGR») оба неверны. Верный корень:

- `kent` умеет цвет. В чистом окружении (`TERM=xterm-256color`, без `NO_COLOR`/`CI`/`FORCE_COLOR`)
  на стартовом экране есть SGR, выбранный пункт `\x1b[1;38;5;33m`, при `COLORTERM=truecolor` —
  `\x1b[1;38;2;48;133;252m`; плюс `OSC 11` (запрос цвета фона). Точное число SGR плавает
  с окном захвата (52–120), поэтому как критерий годится только «есть/нет».
- Цвет отключают по отдельности: `NO_COLOR=1` → 0 SGR, `CI=1` → 0 SGR, `TERM=dumb` → 0 SGR.
  `FORCE_COLOR=0` на `kent` не влияет. Комбинация «как на стенде» → 0.
- Раннер (моя shell-сессия) выставляла `TERM=dumb`, `NO_COLOR=1`, `FORCE_COLOR=0`, `CI=1`,
  и хост наследовал это. Прежние замеры «0 SGR при любом окружении» были загрязнены этим.
- Панель исправна: с чистым окружением xterm.js ставит `xterm-bold xterm-fg-231` →
  `rgb(255,255,255)`, `xterm-fg-33` → `rgb(0,135,255)`, `xterm-fg-103` → `rgb(135,135,175)`,
  `xterm-dim xterm-fg-103`. `TerminalEmulator.tsx` по цвету не менялся.
- Уточнение формулировки: `TERM=dumb` наследует **процесс хоста** от лаунчера; внутри PTY
  `TERM` уже `xterm-256color`, его подставляет AHP-хост. Остальные переменные PTY наследует
  от процесса хоста.
- В AHP 1.1.0 у `CreateTerminalParams` нет поля `env`, поэтому единственный рычаг — окружение
  лаунчеров: `scripts/start-host.sh` (local) и `scripts/start-responses-host.ts` (wbllm/glm)
  через `server/terminal-env.ts`.

Живая проверка после фикса (стенд перезапущен на объединённом коде):
- `ps eww` всех трёх хостов: `TERM=xterm-256color`, `COLORTERM=truecolor`, вредных переменных нет.
- В панели `kent` красит выбранный пункт в `rgb(48,133,252)`; `ArrowDown` переносит подсветку
  с «Create a new project…» на «AgentHostProtocolMicrosoft».
- `npm test` 489/489, `npm run typecheck` чисто.

Неблокирующие замечания gate (переносить в отдельную задачу, не терять):
проводка `terminalEnv` в `start-responses-host.ts` не покрыта тестом (удаление вызова оставляет
`npm test` зелёным); интеграционный тест перебирает пять литеральных имён и не поймает шестую
переменную, добавленную только в bash или только в TS; `e2e/terminal-ansi.spec.ts` опирается на
локаторы AGENTHOS-27 — после слияния #19 это не ломается, но SGR-проверку логичнее держать
в общих хелперах `e2e/support`.
