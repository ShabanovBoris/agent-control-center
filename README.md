# Agent Control Center

Панель для управления сессиями Claude и Codex на нескольких AHP-хостах (Agent Host Protocol).
Панель не запускает агентов сама: она подключается к хостам, которые ими управляют, поэтому те же
сессии остаются доступны из VS Code.

## Запуск

Нужны Node 22+ и VS Code с подкомандой `code agent host`.

```bash
npm install
```

Три процесса, каждый в своём терминале:

```bash
npm run host     # Agent Host VS Code на ws://127.0.0.1:8089, данные в .local/host-data
npm run server   # backend на 127.0.0.1:8090, читает hosts.json
npm run web      # интерфейс на http://localhost:5173
```

При первом запуске `npm run host` VS Code CLI скачивает серверную сборку (~600 МБ) в `~/.vscode/cli/servers`.

VS Code CLI выводит адрес хоста с токеном подключения. `npm run host -- --log` и
`npm run host:gemini -- --log` добавляют вывод в `.local/host.log` и `.local/gemini-host.log`
соответственно и выставляют права `600`. При перенаправлении вывода средствами shell
перед созданием нового файла задайте `umask 077` в том же терминале.

### Обновление агентов и AHP

Кнопка «Обновления» рядом с заголовком проверяет версии SDK, клиента AHP и локального
Agent Host. После подтверждения панель устанавливает обновления и перезапускает
затронутые службы. Для перезапуска хосты должны освободиться от активных задач.
Из панели управляются локальные хосты `local` и `gemini`, запущенные скриптами проекта через VS Code Stable.

`npm run update:agents` загружает стабильные версии Codex App Server и Claude Agent SDK
из npm в `.local/agent-sdks`. Новая версия становится доступна после проверки.
После успешной установки **всех** компонентов команда вызывает `npm run restart:services`
и перезапускает оба локальных хоста и backend. Если хотя бы один компонент не установлен,
службы не перезапускаются. Для запуска со штатными версиями VS Code задайте `AHP_USE_BUNDLED_SDK=1`.

`npm run restart:services` можно выполнить и отдельно после ручного обновления зависимостей.
Команда управляет только двумя хостами из `hosts.json` и backend; основной и резервный UI не перезапускает.
Она проверяет все хосты до первого сигнала процессам, блокируется при активных задачах,
запускает остановленные хосты и повторно проверяет активность перед остановкой запущенных.
Backend заменяется только после успешного подключения обоих хостов. При сбое проверьте
`.local/host.log` и `.local/gemini-host.log`. Backend должен быть запущен заранее:
при его недоступности пакеты могут быть обновлены, но службы не перезапускаются.

Эта же команда проверяет совместимые обновления клиента `@microsoft/agent-host-protocol`.
Новая версия проходит проверку TypeScript и тесты AHP в отдельном каталоге до установки.
Backend использует обновлённую библиотеку при следующем запуске `npm run server`.
Сервер Agent Host обновляется через штатный механизм VS Code CLI.

## Доступ с телефона

На Mac и телефоне подключите одну учётную запись Tailscale. Создайте
`.local/phone-access.json` с HTTPS-адресом этого Mac и логином Tailscale:

```json
{
  "origin": "https://my-mac.my-network.ts.net",
  "login": "me@example.com"
}
```

Выполните `npm run build`, затем запустите или перезапустите `npm run server`.
При наличии этого файла backend отдаёт собранную панель на `127.0.0.1:8092` и разрешает
запросы страницы и WebSocket только для указанного логина через Tailscale Serve.
Опубликуйте её внутри своей сети командой `tailscale serve --bg --https=443 8092`.
При первом запуске Tailscale может попросить включить HTTPS в браузере.
Откройте напечатанный HTTPS-адрес на телефоне. [Документация Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve).

Для доступа с телефона должны работать backend и Agent Host. Во время работы Mac должен
оставаться включённым и бодрствовать. Путь к рабочей папке указывайте на Mac.
После обновления интерфейса пересоберите панель и перезапустите backend.

## Первая настройка агентов

Чтобы подготовить SDK перед первым запуском, выполните `npm run update:agents`. В блоке
«Хосты и агенты» также доступна кнопка «Скачать SDK» для установки с CDN VS Code.
При запуске `npm run host` скрипт подготовит модуль настройки API поверх выбранного
Claude SDK в `.local/claude-sdk`.

Claude использует API-провайдера из `.local/model-provider.env`. Образец настроек —
`model-provider.env.example`: скопируйте его в `.local/model-provider.env`, впишите `API_KEY`
и `BASE_URL`, установите файлу права 600. Ключ не передаётся в браузер и не хранится в Git.

Claude отправляет запросы в Anthropic Messages API провайдера. API-ключ и адрес закрепляются
в программных `settings.env` SDK: этот слой имеет приоритет над `env` из глобального
`~/.claude/settings.json`. Старый `ANTHROPIC_AUTH_TOKEN` и OAuth-токен для этого хоста очищаются,
чтобы они не подменяли выбранный API. Глобальные настройки Claude Code не изменяются;
хранилище истории сессий остаётся прежним. Ключ передаётся модулю через окружение и не записывается
в сгенерированные файлы SDK.

Codex использует прежний вход через ChatGPT (`codex login`) и штатную конфигурацию.
API-провайдер Claude на него не влияет; `~/.codex/config.toml` скриптом запуска не меняется.

Модели семейств Claude задаются переменными
`CLAUDE_SONNET_MODEL`, `CLAUDE_OPUS_MODEL`, `CLAUDE_HAIKU_MODEL`, `CLAUDE_FABLE_MODEL`.
После изменения API-ключа или этих настроек перезапустите `npm run host`.

Codex показывает модели только после первой созданной сессии — до этого их список пуст.
Если сессия Claude не создаётся, проверьте API-ключ, адрес провайдера и лог хоста.
Для Codex проверьте вход ChatGPT на машине хоста. Наличие модели в каталоге не гарантирует
её текущую доступность для генерации.

Рядом с полем сообщения видны модель и уровень reasoning. Панель передаёт уровень по умолчанию
из схемы выбранной модели вместе с сообщением (`message.model.config.thinkingLevel`), если хост
разрешает его менять. Конкретная модель запоминается в браузере для новых сессий этого хоста и
агента. В открытом чате восстанавливается его собственный выбор из черновика или истории.

В форме сообщения рядом с выбором модели доступны режимы, которые объявил хост. У Claude режим управляет подтверждениями
инструментов. У Codex (в том числе Gemini) режим работы и разрешения выбираются отдельно.
Изменение применяется после подтверждения хостом.

## Модели CheapVibeCode через Codex

Дополнительный хост запускается четвёртым процессом:

```bash
npm run host:gemini  # ws://127.0.0.1:8091
```

Он читает `API_KEY` и `BASE_URL` из того же `.local/model-provider.env` и публикует все модели
с корректным `id` из `/v1/models`, включая другие семейства и модели без заявленной поддержки инструментов.
По умолчанию выбирается `gemini-3.8-flash`, если она есть в каталоге, иначе первая модель.
Настроить модель по умолчанию можно через `CHEAPVIBECODE_MODEL` (старое имя `GEMINI_MODEL` также поддерживается).
После изменения настроек перезапустите только `npm run host:gemini`.

В панели создайте сессию на хосте «CheapVibeCode · Codex», агент — Codex. Запросы к модели идут
через OpenAI-совместимый Responses API провайдера. В списке представлены и модели, которые могут
не поддерживать Responses API или инструменты Codex: их наличие в каталоге не гарантирует успешную
генерацию. Регулировка уровня reasoning объявляется для совместимых Gemini, для остальных моделей
используются настройки провайдера по умолчанию. Модели появятся в выборе после создания первой сессии.

У этого хоста отдельные данные (`.local/gemini-host-data`), хранилище Codex (`.local/gemini-codex`)
и токен подключения (`.local/gemini-host-token`). Основной хост «Claude · cheapvibecode + Codex · ChatGPT» продолжает использовать
Codex с входом ChatGPT и Claude с API. Дополнительный хост переиспользует Codex SDK основного хоста.
Если кэш ещё пуст, SDK можно скачать в блоке этого хоста в панели.

## Токены и архив

Под формой сообщения показаны сумма токенов, вход, выход и чтение кэша.
Учитываются все чаты сессии и текущий ход. Панель загружает старые страницы истории;
при ошибке показывает причину и кнопку повтора. Используются снимки usage хоста,
а не сумма входящих уведомлений: переподключение не удваивает расход.
Для Codex берутся суммы всех обращений к модели внутри хода, если хост их публикует.
Чтение кэша включено во вход и не прибавляется повторно к общей сумме.

Заполненность контекста относится к открытому чату. Для Codex и Gemini панель делит сумму
входных и выходных токенов последнего запроса на размер окна, переданный хостом. При отсутствии
данных хоста, в том числе у Claude, панель показывает «нет данных».

Если usage не передан или история неполная, это отмечено явно. Хост VS Code для Claude
не публикует токены записи кэша: показана нижняя граница по доступным данным, а не точный
биллинг провайдера. Счётчик показывает токены, не денежную стоимость.

Кнопка «В архив» меняет состояние сессии на хосте через `session/isArchivedChanged`.
Архивные сессии доступны во вкладке «Архив»; «Восстановить» возвращает возможность
продолжить разговор. Это состояние общее для клиентов, а не локальное скрытие строки.

При удалении через другой AHP-клиент панель закрывает устаревшие подписки и показывает
«Сессия недоступна». Открытие уже удалённого адреса также заканчивается этим сообщением,
если хост отвечает `SessionNotFound` или `NotFound`.
Для не начатых черновиков VS Code может не прислать уведомление: выбранная сессия
дополнительно перепроверяется при возвращении фокуса в браузер и кнопкой «Обновить».

## Выбор рабочей папки

В форме новой сессии кнопка «Выбрать в Finder…» открывает системный диалог выбора папки
на Mac с backend. Выбранный абсолютный путь подставляется в поле; отмена оставляет прежний путь.
Ручной ввод доступен для всех хостов.

«Недавние папки» хранит восемь последних директорий после успешного создания сессии.
История сохраняется в этом браузере, отдельно для каждого хоста; повторный выбор переносит
папку наверх списка. Ошибка сохранения истории не отменяет уже созданную сессию.

## Конфигурация

`hosts.json`:

- `listen.host` — адрес входящего backend listener. Разрешены только `127.0.0.1` и `::1`;
  точное значение `localhost` при загрузке заменяется на `127.0.0.1`. Другие адреса и имена,
  включая `0.0.0.0`, отклоняются до подключения к AHP-хостам и открытия сокетов: backend
  исполняет команды агентов от вашего имени, а проверка `Origin`/`Host` не аутентифицирует
  произвольного сетевого клиента. Доступ с телефона настраивается отдельно через Tailscale Serve.
- `listen.port` — порт backend (по умолчанию `8090`).
- `agents` — какие агенты показывать (по `provider`); без списка показываются все.
- `hosts` — AHP-хосты: `id`, `label`, `url` и `tokenFile` с токеном подключения. Ограничение
  `listen.host` не ограничивает исходящие подключения backend к удалённым `hosts[].url`.
- `hosts[].defaultModels` — модели панели по умолчанию для агентов, которые не объявляют их
  по AHP. Ключ — id агента, значение — id модели из каталога этого хоста.
- `hosts[].localFilesystem: true` — файловая система хоста совпадает с Mac, на котором работает
  backend. Только для таких хостов на macOS доступен Finder. Для SSH-пробросов к удалённым
  машинам этот флаг не устанавливайте: локальная папка не является папкой удалённого хоста.
- `debugPort` — порт резервной панели, по умолчанию `5174`.

Основная и резервная панели читают один и тот же `hosts.json`. Резервная панель запускается
командой `npm start --prefix debug-ui` на `http://127.0.0.1:5174` и подключается к тем же
двум AHP-хостам напрямую. После изменения `hosts.json` её нужно перезапустить отдельно.
Токены читают backend и сервер резервной панели; в браузер они не попадают.

Удалённый хост проще всего подключить через SSH-проброс порта и добавить в `hosts` как ещё одну запись:

```bash
ssh -N -L 8189:127.0.0.1:8089 user@remote
```

## Разработка

```bash
npm run typecheck
npm test
npm test --prefix debug-ui
```

`npx tsx scripts/probe.ts` проверяет AHP-хост напрямую с общим таймаутом 10 секунд.
`npx tsx scripts/backend-check.ts` проверяет backend. Таймаут подключения — 5 секунд,
время ожидания после подключения задаёт `CHECK_WAIT_MS` (по умолчанию 3000 мс).
По умолчанию доступны сводка, подписки и команды чтения. Для команд, меняющих состояние хоста,
передайте `--write` первым аргументом перед JSON-командами.

## Устройство

- `server/hub.ts` — соединения с хостами через `MultiHostClient` из SDK, перевод команд UI в AHP actions.
- `server/mirror.ts` — зеркало состояния каналов; упорядочивает снимки и actions по `serverSeq`.
- `shared/` — контракт backend ↔ браузер и общие редьюсеры: браузер получает снимок и actions
  и применяет те же редьюсеры SDK, что и backend.
- `src/` — интерфейс на React.
- `scripts/claude-provider.mjs` — настройки API для `query`, `startup` и `prewarm` Claude SDK;
  остальные экспорты, включая историю сессий, делегируются установленному SDK без изменения.

## Ограничения

- Статус SDK агентов и запрос на его скачивание идут через служебные ключи VS Code в root config,
  а не через стандартный AHP; на других хостах этого блока не будет.
- Copilot в панели скрыт списком `agents`. Сам хост VS Code регистрирует его всегда, отключить
  его на хосте нельзя; для работы ему понадобился бы GitHub-токен от клиента, чего панель не умеет.
- Просмотр файлов ограничен правками конкретного хода: `FileEditDisplay` показывает данные
  `FileEdit` из результатов успешных вызовов инструментов, а для хода из истории без прямых данных
  может запросить `turn`-changeset при распознанном успешном вызове инструмента правки, если хост
  публикует шаблон URI хода. Текстовый diff доступен, если хост сохранил читаемые версии файлов.
  Это не файловый браузер и не просмотр произвольных изменений на диске.
- Отдельного просмотра терминалов нет. Команда и текстовый результат могут быть видны в карточке
  инструмента, но `TerminalOutput` к сессии не подключён.
- Нет выбора из нескольких рабочих папок и подтверждения результата инструмента.
- Пути рабочих папок — только POSIX.
- Смену модели в уже идущей сессии Claude хост не применяет: ход выполняет прежняя модель.
  На первом ходе новой сессии выбор работает; Codex меняет модель и посреди сессии.
  Под каждым завершённым ходом панель показывает модель, которая его выполнила;
  то же по всей сессии выводит `npx tsx scripts/turn-models.ts <hostId> <ahp-session:/…>`.
- Повторный ответ на одно подтверждение хост VS Code не отклоняет, а принимает; инструмент при этом
  выполняется один раз. Backend сам отсекает ответ на вызов, который уже не ждёт подтверждения.

## UI Компоненты

Интерфейс включает набор компонентов для работы с расширенными возможностями агентов:

### Основные компоненты
- **ConfigPanel** — выбор режима работы (default/acceptEdits/plan/auto)
- **ChatSourceMenu** — боковой чат от текущего или последнего завершённого хода и форк переписки до последнего завершённого хода
- **ReasoningBlock** — свёрнутый блок рассуждений агента (вместо старого встроенного)
- **ToolResultsDisplay** — отображает `Text` как текст, для `EmbeddedResource` показывает превью
  PNG/JPEG/GIF/WebP, а для остальных форматов — только MIME-тип. `Resource` показывает URI обычным
  текстом, не открывая и не скачивая ресурс. В SDK 1.1.0 в `ToolResultContent` нет отдельных типов
  `Image` и `File`; `FileEdit` обрабатывается отдельно от карточки результата компонентом
  `FileEditDisplay`. Типы `Terminal` и `Subagent` эта карточка также не отображает.

### Вспомогательные компоненты
- **AttachmentUpload** — загрузка изображений через file input
- **MessageView** — отображение сообщений с вложениями
- **FileEditDisplay** — список правок конкретного хода по данным `FileEdit` из успешных вызовов
  инструментов или, для хода из истории без прямых данных, по `turn`-changeset при распознанном
  успешном вызове инструмента правки и опубликованном хостом шаблоне URI хода. Текстовый diff
  строится по сохранённым версиям от хоста; общего файлового браузера и просмотра произвольных
  изменений на диске нет.
- **TerminalOutput** — форматированный вывод команд; к сессии не подключён, отдельного просмотра
  терминалов нет
- **SubagentCard** — карточка информации о подагенте

### Основные операции API
- `createChat` — создание нового чата с поддержкой fork и side-chat
- `fetchTurns` — получение истории сообщений курсором
- `readResource` — чтение ресурса с хоста
- `updateSessionConfig`/`updateChatConfig` — изменение конфигурации

### Особенности
- Вложения в сообщениях преобразуются в `Message.attachments`
- Поддержка видения моделей отражена в `ModelOverview.supportsVision`
- Возможности агента (`multipleChats`, fork/side-chat) через `AgentCapabilities`
- Иконка скрепки без текста для экономии места в композере
